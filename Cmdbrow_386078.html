qingxinotepad 对照 Windows Notepad：功能盘点、补齐与 BUG 排查

日期：2026-11-07 · 版本：1.2.0 · 产物：dist\qingxinotepad_install.exe（1,734,881 字节）、dist\qingxinotepad-portable-1.2.0.zip

一、对照结论

qingxinotepad 不是「纯 Notepad 复刻」，它在 Notepad 基础上还叠了 IDE 级能力（96+ 语言语法高亮、符号扫描、编译/报错红行、库下载、多标签、自绘菜单、编译窗口）。 下面只比对「Notepad 有、本程序没有」的缺口，IDE 级功能不计入缺口。

Notepad 功能 本程序状态 本轮处理
新建 / 打开 / 保存 / 另存为 / 打印 / 页面设置 已有 —
撤销 / 重做 / 剪切 / 复制 / 粘贴 / 删除 / 全选 / 时间日期 已有 —
查找 / 查找下一个 / 查找上一个 / 替换 / 转到行 已有（但缺选项） 补齐「区分大小写」「查找方向（向下/向上）」
自动换行 / 字体 / 缩放（25%~500%） 已有 —
状态栏（行列、编码、行尾、缩放、语言） 已有 —
深色模式 / 背景图 / 透明度 / 置顶 / 更换图标 已有（超出 Notepad） —
拖放打开文件 / 命令行打开文件 / 最近文件 已有 —
编码切换（ANSI / UTF-8 / UTF-8 BOM / UTF-16 LE / UTF-16 BE） 原先完全没有 新增 格式 → 编码 子菜单，切换即按新编码重写文件
行尾切换（CRLF / LF / CR） 原先完全没有 新增 格式 → 行尾 子菜单，切换即转换已存盘文件

拼写检查 未实现 未做：本程序定位为代码/文本混合编辑器，中文环境拼写检查价值低，属可选项

二、新增功能（已实测）

1. 格式 → 编码（5 项）

菜单：格式 → 编码 → UTF-8 / UTF-8 带BOM / UTF-16 LE / UTF-16 BE / ANSI

  • 菜单 ID：IDM_FORMAT_ENC_BASE = 40110（+0…+4）
  • 行为：切换后若已关联磁盘文件，立即以新编码重写该文件；写入失败则回退原编码并提示。
  • 当前编码在菜单中打勾，同时在状态栏第 2 段实时显示。

2. 格式 → 行尾（3 项）

菜单：格式 → 行尾 → Windows (CRLF) / Unix (LF) / Macintosh (CR)

  • 菜单 ID：IDM_FORMAT_EOL_BASE = 40120（+0…+2）
  • 行为：与编码一致，切换即转换已存盘文件的行尾；状态栏第 3 段实时显示。

3. 查找 / 替换选项

  • 新增「区分大小写」复选框与「方向（向下 / 向上）」单选。
  • 查找框 420×150、替换框 420×172（原尺寸底部留白 / 按钮被裁，本轮一并修正搬运）。
  • 全部替换后主动标记文档已修改（标题出现 *），符合 Notepad 行为。

三、排查出的 BUG 与修复

# BUG 影响 修复
1 IDM_FILE_RECENT_BASE 与 IDM_BUILD_LANG_BASE 同为 40100 最近文件菜单项与「编译 → 语言」菜单项 ID 撞车，点语言项会误走最近文件逻辑 IDM_FILE_RECENT_BASE 改为 40200
2 file.cpp 的 EncodeText 用 WideCharToMultiByte(..., -1, ...) 长度把结尾 NUL 算进去，缓冲区只 resize(len-1)，越界写 1 字节（堆破坏）；UTF-8 与 ANSI 两条分支都有 传显式 srcLen，按实际长度分配
3 dialog.cpp 的 MakeDialogButtonsOwnerDraw 把所有 Button 强制改为 BS_OWNERDRAW 新增的复选框 / 单选按钮会被画成空白 跳过 CHECKBOX / RADIOBUTTON / 3STATE / GROUPBOX
4 ConfirmDiscard() 在 IDYES 分支无条件 return true 用户在「保存？」里点「是」但保存对话框被取消 / 写盘失败时，仍会丢弃修改（丢数据） 改为 return !g_state.modified
5 SaveToPath 不检查 WriteFile 返回值 磁盘满 / 无权限时静默失败，文件半截 改 bool、检查返回值、失败删除半截文件并刷新状态栏
6 LoadFile 未处理 ReadFile 失败 / 短读 读失败时可能拿到不完整内容 增加失败与短读处理
7 文本行索引每次从 0 扫描（LineStart() 线性查找） 整篇遍历退化为 O(n²)：打开 2.4 MB 文本时 UI 卡死 60 秒以上仍无响应（Notepad 秒开） 新增 lineStarts 行首偏移缓存 + 失效标记，LineStart/LineCount/LineOfOffset 全部改缓存（后者用二分）

四、实测证据

编码 / 行尾（读文件字节，不看界面）

测试文件 hello\r\n世界\r\n（UTF-8 无 BOM）：

操作 文件字节结果
切 UTF-8 带BOM 头变为 EF BB BF
再切 LF 无 CRLF，仅 LF
再切 ANSI 无 BOM，中文变 GBK（CA C0 = “世”）
恢复 CRLF + UTF-8 BOM 字节复原

2.4 MB 大文件（60,000 行，含中文）压测：

操作 耗时 结果
打开 0.84 s（修复前 > 60 s 仍无响应） 正常显示
转 ANSI 0.01 s 2,100,000 B
转 LF 0.02 s 2,040,000 B（-60,000 = 去掉 60,000 个 CR）
转 UTF-8 BOM 0.02 s 2,340,003 B（+3 字节 BOM）
转 CRLF 0.02 s 2,400,003 B（+60,000 CR）
连打 30 个字符 1.04 s（约 35 ms/键） 进程存活
